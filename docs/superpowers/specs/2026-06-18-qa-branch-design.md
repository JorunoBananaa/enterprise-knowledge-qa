# QA 分支功能设计

## 背景

问答页已经在回答操作区预留“分叉”入口，但当前 `QAPage` 中的处理逻辑仍是占位日志。现有后端会话模型是线性的 `ChatSession -> ChatMessage -> Citation`，`/qa/ask/stream` 会从当前会话最近消息中加载上下文。因此本功能采用“创建普通新会话并复制历史”的方式实现分支，不引入树状消息关系。

## 目标

用户点击某条回答的“分叉”后，系统以该回答为截止点创建一个新会话。新会话包含原会话中从第一条到目标回答对应消息的所有问答和引用来源，不包含目标消息之后的内容。创建成功后前端立即进入新会话，用户可以在新会话中继续追问。

## 范围

包含：

- 新增后端分支接口。
- 服务端校验消息归属，并复制会话、消息和引用。
- 前端将现有“分叉”按钮接入接口。
- 分支成功后刷新历史会话并跳转到新会话。
- 失败时保留当前会话并显示错误。

不包含：

- 同一会话内的树状分支切换。
- 分支命名弹窗。
- 分支来源展示。
- 修改 `/qa/ask/stream` 请求协议。
- 新增数据库父子分支字段。

## 产品行为

点击回答下方的“分叉”按钮后：

1. 系统请求后端创建分支会话。
2. 分支会话标题保持与原会话标题一致，不追加后缀。
3. 创建成功后前端跳转到 `/qa?session_id=<new_session_id>`。
4. 左侧历史会话刷新，新会话成为当前选中项。
5. 成功时不弹提示。
6. 失败时显示“创建分支失败”，并停留在当前会话。

只有已经落库且已结束的回答可以分叉。前端允许 `id > 0` 且 `result_status` 不属于 `streaming`、`aborted`、`error` 的回答触发分支请求；未完成的流式占位消息、取消中消息、错误消息或 `id <= 0` 的本地临时消息不能触发分支请求。

## 后端设计

新增接口：

```http
POST /qa/messages/{message_id}/fork
```

请求体为空。响应：

```json
{
  "session_id": 123
}
```

接口流程：

1. 根据 `message_id` 查询目标 `ChatMessage`，并关联其 `ChatSession`。
2. 校验目标会话的 `user_id` 等于当前登录用户 ID。
3. 如果目标消息不存在、目标会话不存在或不属于当前用户，统一返回 404。
4. 按原会话内时间正序读取从第一条到目标消息为止的消息。复制范围必须以目标消息为截止，不复制后续消息。
5. 创建新 `ChatSession`，`user_id` 与原会话一致，`title` 与原会话标题一致。
6. 逐条复制 `ChatMessage` 的 `question`、`answer`、`result_status`。
7. 逐条复制对应 `Citation`，新引用指向新消息 ID，引用内容与原引用一致。
8. 提交事务并返回新会话 ID。

复制逻辑应放在后端服务层或当前 `qa.py` 的清晰辅助函数中，避免把批量复制细节散落在路由函数里。复制过程使用一次事务；任何消息或引用复制失败都回滚，不创建半截分支。

## 前端设计

`ChatMessageItem` 继续渲染回答区的“分叉”操作。`QAPage` 将现有 `handleForkAnswer` 的日志占位替换为真实请求逻辑：

1. 点击“分叉”时调用 `POST /qa/messages/{msg.id}/fork`。
2. 请求期间禁用当前分叉动作，避免重复点击同一条消息。
3. 成功后更新 URL 到 `/qa?session_id=<new_session_id>`，让页面按现有逻辑加载新会话详情。
4. 调用本页 `loadSessions()`，并派发 `qa:sessions-updated`，让 `AppShell` 历史侧栏同步刷新。
5. 成功时不调用 `message.success`。
6. 失败时调用 `message.error("创建分支失败")`。

前端只负责发起目标消息 ID，不能把消息历史传给后端作为复制来源。历史复制、权限校验和引用复制都由后端完成。

## 数据流

```text
用户点击回答分叉
  -> QAPage 调用 POST /qa/messages/{message_id}/fork
  -> 后端校验消息归属
  -> 后端复制截止到目标消息的历史到新 ChatSession
  -> 后端返回 new_session_id
  -> 前端切换 URL 到 /qa?session_id=new_session_id
  -> QAPage 加载新会话详情
  -> QAPage 和 AppShell 刷新历史会话
```

新会话后续提问继续使用现有 `/qa/ask/stream`。由于新会话已经持久化了复制后的消息，现有 `_load_chat_history` 会自然从新会话中读取上下文。

## 错误处理

- 目标消息不存在：404。
- 目标消息不属于当前用户：404。
- 目标消息所属会话已删除：404。
- 复制范围为空：404；正常数据下不会发生。
- 复制事务失败：回滚，并让接口返回错误。
- 前端接口失败：显示“创建分支失败”，不跳转、不刷新当前消息列表。

## 测试计划

后端：

- 分支只复制从第一条到目标消息为止的消息，不复制后续消息。
- 引用复制后指向新消息 ID，引用字段与原引用一致。
- 分叉其他用户的消息返回 404。
- 复制过程中失败时不保留半截会话。

前端：

- `id > 0` 且 `result_status` 不属于 `streaming`、`aborted`、`error` 的回答才会触发分支请求。
- 分支成功后刷新历史并跳转到新会话。
- 分支成功不显示成功提示。
- 分支失败只显示“创建分支失败”，并留在当前会话。

## 验收标准

- 用户能从任意已完成回答创建分支会话。
- 新会话标题与原会话标题一致。
- 新会话只包含目标回答及其之前的消息和引用。
- 成功后立即进入新会话，并可以继续追问。
- 左侧历史会话列表能显示新会话并选中当前会话。
- 不能分叉其他用户的消息。
- 失败时当前会话不丢失、不跳转，只显示失败提示。
